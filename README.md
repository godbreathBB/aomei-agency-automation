# 奥美架构自动化

一套可复用的**多智能体广告团队运行配置**：把策略、创意、寻源、公关、执行、合规六个角色，与三道人工闸门、四个 Skill、三个定时任务编排成 T1–T6 流水线。

> 本仓库仅含配置与文档，不含真实客户资料、品牌资产或历史 Demo 产物。

## 目录结构

```
.
├── AGENCY.md                  # 团队宪法：唯一真相源，权限表、闸门、验收标准
├── 02_进行中/

├── .codebuddy/agents/         # 六个角色的完整定义
│   ├── lead.md                # 客户群总调度（只委派，不产出）
│   ├── strategist.md          # 策略总监
│   ├── creative.md            # 创意总监
│   ├── scout.md               # 寻源官

│   ├── exec.md                # 执行官（唯一外部发送权）
│   └── compliance.md          # 合规官（一票否决权）
├── .workbuddy/skills/         # 四个项目级 Skill
│   ├── brief-writer/          # 需求 → 结构化 Brief
│   ├── creative-redteam/      # 创意方向六视角红队测试
```

## 角色与权限

| 角色 | 代号 | 核心职责 | 可写范围 | 联网 | 外部发送 |
| --- | --- | --- | --- | --- | --- |
| 客户群总调度 | lead | 拆解、派发、催办、汇总 | `02_进行中/status.json` | 否 | 否 |
| 策略总监 | strategist | 消费者洞察、竞品、定位 → Brief | T2 Brief + `research_notes.md` | 是 | 否 |
| 创意总监 | creative | 3 个差异化创意方向 | T3 创意方向 + `06_物料/sketch_*` | 否 | 否 |
| 寻源官 | scout | 公开信息采集、事实与选项 | 寻源卡 + `01_客户档案/` | 是 | 否 |
| 公关官 | pr | 媒体策略、信息屋、危机预案 | T4 公关方案 + `06_物料/pr/` | 是 | 否 |
| 执行官 | exec | 排期、协调、制作管理、打包交付 | 排期表 + `08_交付包/` | 否 | **是（仅 G6 后）** |
| 合规官 | compliance | 逐项合规审查、一票否决 | T5 质检报告 + 禁用词表 | 是 | 否 |

## 工作流 T1–T7

```
T1 寻源 → T2 策略 → T3 创意 → T4 并行支路（公关‖执行‖物料）→ T5 质检 → T6 交付 → T7 归档
```

**交接契约 C1–C4**：C1 寻源卡→strategist；C2 Brief→creative/pr；C3 创意方向→exec/pr/compliance；C4 质检报告→exec/Lead。字段固定，下游只读上游落盘文件，不读对话历史。

**三道人工闸门（必须停下问用户，不得代行放行）**

| 闸门 | 节点 | 确认内容 |
| --- | --- | --- |
| G2 | T2→T3 | 策略方向是否认可，有无调整 |
| G3 | T3→T4 | 选择哪个创意方向推进 |
| G5 | T5→T6 | 是否同意交付，有无修改意见 |
| G6 | T6 对外发送前 | exec 唯一外部发送权的放行点 |

闸门提问采用封闭式选项（如 A 认可／B 调整／C 重做），不抛开放式问题。

## Skill 说明

- **brief-writer**：把口语化需求转成结构化 Brief（目标/受众/单一主张/约束/验收口径/依据）。
- **creative-redteam**：对 3 个方向做六视角「最蠢解读」攻击，输出 1–5 评分、风险等级与推荐排序。
- **brand-guard**：广告法、数据合规、KOL 报备、品牌安全预检，红黄绿灯，一票否决。
- **delivery-packager**：扫描 `06_物料/`，按七目录标准整理到 `08_交付包/`，生成 `00_README.md`；只复制不删改。

## 定时任务（需在工作区重新激活）

| 名称 | 频率 | 执行者 | 产物 |
| --- | --- | --- | --- |
| 每周交付复盘 | 每周一 09:00 | lead | `04_复盘/周报_YYYYMMDD.md` |
| 每月资料库更新 | 每月 1 日 10:00 | scout | `04_复盘/月度更新_YYYYMM.md` |
| 每日舆情晨报 | 工作日 08:30 | pr | `04_复盘/舆情日报_YYYYMMDD.md` |

## 使用方法

1. 将本目录内容复制到 WorkBuddy 工作区根目录（保留隐藏目录 `.codebuddy/`、`.workbuddy/`）。
2. 按真实项目补齐 `00_品牌资产/` 与 `01_客户档案/`；当前两者均为模板/占位，无真实数据。
3. 由 Lead 按阶段派发任务；到 G2/G3/G5 闸门时必须向用户确认。
4. 产物命名：`T序号_阶段名_日期.md`；物料命名：`[物料类型]_[品牌]_[版本].ext`。

## 边界与声明

- 单一真相源：所有成员只认工作目录文件，不依赖对话记忆。
- 角色不越界：策略不写创意，创意不写策略，执行不创作，寻源不下结论，合规不当教练。
- 所有沟通经 Lead 中转，成员之间不直接传稿。
- 信息必须标注来源与置信度；查不到写「未提供/未找到确凿依据」，禁止编造。
- 外部发送权仅 `exec` 持有，且必须 T5 通过 + G6 人工放行。
- 定时任务为平台自动化配置，克隆后需按目标工作区重新创建。
