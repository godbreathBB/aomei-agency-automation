# Brand Guard

## 目的

把"能不能发出去"的判断前置到创意阶段，避免合规问题在交付末端才爆雷。compliance 的 KPI 是没出事，不是过得快。

## 使用时机

- T3 创意方案出口前自检。
- T4 公关 / 执行 / 物料三支路出口前预检。
- G5 质检闸门前，由 compliance 正式出具意见。

## 检查项

| 项 | 红灯示例 | 依据要求 |
|---|---|---|
| 广告法 | 绝对化用语、虚假功效、数据无出处 | 引用具体法条；不确定写"未找到确凿依据" |
| 数据合规 | 未经授权使用用户数据、跨境传输 | 引用隐私政策条款 |
| KOL 报备 | 达人合作未标注、未走报备流程 | 引用平台规则 |
| 品牌安全 | 与竞品对比失实、调性冲突 | 引用 `00品牌资产/` 具体段落 |
| 危机红线 | 敏感议题、历史舆情冲突 | 引用 `01客户档案/` 危机记录 |

## 输出格式

```markdown
# 品牌合规预检｜<方案名> v<N>
| 项 | 灯 | 问题 | 依据 | 整改建议 |
|---|---|---|---|---|
| 广告法 | 红/黄/绿 | | | |
## 结论
- 红灯数：N（>0 即一票否决，不得进入 G6）
- 待拍板项：
```

## 规则

- 没有确凿依据不得写成"违法"；写"存疑，建议法务确认"。
- 红灯不可由非 compliance 角色解除。
- 被否决方案保留在 `02进行中/_rejected/`，不删除。
