# Delivery Packager

## 用途

将 `06_物料/` 中的最终成品，按标准交付结构整理到 `02_进行中/08_交付包/`，生成交付清单与使用说明。**只复制和整理，不修改原始物料，不删除 `06_物料/` 中的文件。**

## 调用方式

```
调用 delivery-packager，输入：物料目录 = 06_物料/，项目元数据 = 从 02_进行中/05_排期表.md 提取
```

调用者必须是 `exec`，且必须满足：T5 质检通过、`07_质检报告.md` 无红灯、G6 人工放行。未满足则拒绝打包并回报 Lead。

## 输入

- 物料目录：`06_物料/`（TVC.mp4、KV.jpg、文案.docx 等最终文件）。
- 项目元数据：从 `02_进行中/05_排期表.md` 提取项目名称、客户、日期、版本号。

## 输出结构

```
02_进行中/08_交付包/
├── 00_README.md              # 交付说明（客户名称、项目简述、文件清单、使用指引）
├── 01_创意方案/              # 创意方向终稿 PDF/Markdown
├── 02_视觉物料/              # KV、海报、社交媒体图（按渠道分文件夹）
├── 03_视频音频/              # TVC、短视频、音频（含字幕文件）
├── 04_文案稿件/              # 脚本、软文、新闻稿、口号列表
├── 05_排期与执行记录/        # 排期表、修改记录、签字确认单
└── 06_技术文件/              # 字体包、源文件（PSD/AI）、代码片段
```

## 处理逻辑

1. 扫描 `06_物料/` 全部文件，按文件类型与命名前缀归类到上述七个目录。
2. 缺失的必要文件（如品牌手册、VI 规范）从 `00_品牌资产/` 复制一份到 `06_技术文件/`。
3. 生成 `00_README.md`，包含：
   - 项目名称与客户
   - 交付日期与版本号（从 `05_排期表.md` 读取）
   - 文件清单（每个文件路径、用途、格式、尺寸/时长）
   - 注意事项（字体版权、分辨率要求、使用期限、联系人）
   - 残留风险（引用 `T5_质检报告_YYYYMMDD.md` 中未修改的低严重度项）
4. 发现命名不规范或缺失关键文件时，在 README 中标记"待确认"，并返回警告信息给调用者。
5. **不覆盖已有 `08_交付包/`**：若已存在，须先由 exec 归档到 `03_交付归档/` 再重新打包。
6. 打包完成后输出成功消息及交付包绝对路径；由 exec 回报 Lead，等待 G6 放行后对外发送。

## 约束

- 不修改原始物料文件，只复制与整理。
- 不删除 `06_物料/` 中的文件，保留原始工作区。
- 若 `06_物料/` 为空，报错并拒绝打包。
- 不把敏感联系人信息写进公开 README。
- 版本号不覆盖已有归档；新版本递增。
- 交付包生成后由 Lead 触发 G5/G6 闸门，用户确认后 exec 才对外发送。
